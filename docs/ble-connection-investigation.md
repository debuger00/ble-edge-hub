# BLE 连接稳定性排查记录（2026-10-16）

目标：四台 IMU948 和四台 MD9930 同时持续采样。`ready` 只表示 GATT 就绪，验收还需有效采样持续到达、频率和间隙统计及断线次数。目前尚未完成八路稳定验收。

## 已确认的事实

- 网关蓝牙固件 `KLB0012V4.3.5`；网络固件 `KLW0003V4.4.4`。
- 读回预设：拒绝设备更新连接参数，间隔 40–40 ms，latency 0，监督超时 4000 ms。普通扫描窗口/间隔均为 30 ms；连接扫描备选项关闭；连接事件扩展关闭；连接发射功率 0。
- HCI `0x08` 是 BLE 连接监督超时，不是 WebSocket 或 TensorRT 错误，也不等于连接数量超限。
- `C9 01 01` 在服务端尚未发送命令时也出现；其中失败原因 `01` 表示未知命令。当前后端未发送 `0xC9`，不能把这个回复归因于 `0x10` 连接请求。两个固件版本不同不直接证明固件不兼容。
- 007 的 GATT 查询已成功。实际 UUID 到 value handle 映射如下，来源为网关 `0x24` 回复：

| UUID | 用途 | Value handle | CCCD |
|---|---|---|---|
| FFF1 | MD9930 采样通知 | 0x000B | 0x000C |
| FFF2 | 电量读取 | 0x000F | 无 |
| FFF3 | 命令写入 | 0x0012 | 无 |
| FFF4 | 参数写入 | **0x0015** | 无 |
| FFF5 | 命令结果读取 | 0x0018 | 无 |

`0x0014` 是 FFF4 声明句柄，旧配置将采样周期写错了位置。已将 MD9930 参数写入配置及示例修正为 `0x0015`。其他设备/固件仍需结合实测核对；句柄不是 UUID 的通用常量。

## 代码修复

- 初始化设备时原先只分配一个命令编号，却发送两条命令，导致后续命令复用编号。现在原子预留两个编号。
- 仅向 `ready` 的 IMU 查询电量；重复 `ready` 上报不重复初始化，实际重连后仍会初始化。
- IMU948 的单字节 `29`、`12` 是合法确认回复，不再当成损坏采样包。
- 真正解析失败时记录句柄、原始 payload 和累计次数，并限制重复日志。
- 输出 `0x27` 的实际连接间隔和监督超时；`gateway-info` 读回预设参数以及各设备 `0x13` 状态。
- 交互 CLI 空闲等待可响应 SIGINT/SIGTERM，避免旧后端占住 7628/8765。
- 损坏数据后的帧同步成段跳过噪声，避免逐字节日志风暴；保留跨 TCP 分片的帧头，支持 MAC/RSSI-only 扫描帧。
- 新增 IMU `subscribe_tag` 配置，缺省仍为 `0x0FFF`。`0x000F` 保留已使用的 accel/raw_accel/gyro/mag，将当前 73 字节采样缩减为 31 字节；稳定性对照尚在进行。
