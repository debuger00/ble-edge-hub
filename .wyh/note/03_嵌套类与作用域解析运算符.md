# 03 嵌套类与作用域解析运算符

## 一、`TcpServer::Session` 不是继承关系

在 `src/services/tcp_server.cpp` 中：

```cpp
class TcpServer::Session {
  // ...
};
```

这里的 `::` 叫“作用域解析运算符”，表示：

> 定义属于 `TcpServer` 作用域中的 `Session` 类。

它不是继承关系。

如果是继承，写法通常是：

```cpp
class Session : public TcpServer {
};
```

或者：

```cpp
class TcpServer : public Session {
};
```

当前代码中没有 `: public` 或 `: private`，所以不存在继承。

## 二、`Session` 在头文件中的前置声明

`include/iot/services/tcp_server.hpp` 中只声明了：

```cpp
class TcpServer {
 private:
   class Session;

   std::unordered_map<std::uint64_t, std::shared_ptr<Session>> sessions_;
};
```

```cpp
class Session;
```

叫“前置声明”，意思是先告诉编译器：

> `TcpServer` 内部有一个叫 `Session` 的类，完整内容稍后定义。

之后在 `.cpp` 文件中使用：

```cpp
class TcpServer::Session {
  // 完整定义
};
```

## 三、`Session` 在本项目中的作用

`Session` 表示一个 TCP 网关连接会话。

每当有新的网关连接时，`TcpServer` 就创建一个 `Session`：

```cpp
auto session = std::make_shared<Session>(
    id, client, config_, database_, websocket_, inference_);
sessions_[id] = session;
session->start();
```

可以理解为：

```text
TcpServer
├── Session 0：管理网关 A
├── Session 1：管理网关 B
└── Session 2：管理网关 C
```

每个 `Session` 负责：

- 一个 TCP socket；
- 一个网关连接；
- 一个工作线程；
- TCP 字节流解码；
- 网关设备发现状态；
- 设备连接状态；
- 待发送命令队列；
- 电池查询和自动重连。

## 四、`TcpServer` 和 `Session` 的关系

它们是“拥有/组合”关系，而不是继承关系。

```text
TcpServer
    └── 拥有多个 Session
            └── 每个 Session 管理一个 TCP 网关连接
```

`TcpServer` 通过下面的成员保存多个会话：

```cpp
std::unordered_map<std::uint64_t, std::shared_ptr<Session>> sessions_;
```

因此：

- `TcpServer` 是 TCP 连接管理器；
- `Session` 是单个网关连接的处理器。

## 五、为什么不直接写在 `TcpServer` 大括号里？

以下写法也是合法的：

```cpp
class TcpServer {
 private:
   class Session {
    public:
      void start() { /* ... */ }

    private:
      int socket_;
      std::thread worker_;
   };
};
```

但当前项目选择把 `Session` 的完整定义放到 `.cpp` 文件，主要是为了实现“接口与实现分离”。

头文件只保留：

```cpp
class Session;
```

源文件再提供完整实现：

```cpp
class TcpServer::Session {
  // socket、线程、锁、队列等内部细节
};
```

## 六、这种写法的好处

### 1. 头文件更简洁

`Session` 内部有很多实现成员：

```cpp
int socket_;
std::thread worker_;
std::mutex state_mutex_;
std::deque<Bytes> outgoing_;
```

把这些放在 `.cpp` 中，可以避免头文件过于复杂。

### 2. 隐藏实现细节

外部代码只需要使用：

```cpp
tcp.start();
tcp.stop();
tcp.snapshots();
tcp.connect_device(...);
```

不需要知道 `Session` 如何接收数据、如何加锁或如何维护命令队列。

### 3. 减少编译依赖

如果完整定义写在头文件中，所有包含 `tcp_server.hpp` 的源文件都会看到 `Session` 的所有实现细节。

之后只要修改 `Session` 的成员，很多源文件可能都需要重新编译。

使用前置声明可以减少头文件暴露的内容和编译依赖。

### 4. 限制外部使用

由于 `Session` 位于：

```cpp
private:
  class Session;
```

所以它是 `TcpServer` 的私有嵌套类。外部代码不能直接创建或操作它，只能通过 `TcpServer` 提供的公开接口间接使用。

## 七、`TcpServer::start()` 也是相同的语法

头文件中声明：

```cpp
class TcpServer {
 public:
   void start();
};
```

源文件中定义：

```cpp
void TcpServer::start() {
  // ...
}
```

这里的 `TcpServer::` 表示：

> `start()` 函数属于 `TcpServer` 类。

因此下面两种写法的共同点是：

```cpp
void TcpServer::start();
class TcpServer::Session { };
```

都是在类外部通过 `::` 明确指定所属作用域。

## 八、一个容易忽略的细节

虽然 `Session` 是 `TcpServer` 的嵌套类，但它不会自动拥有外层 `TcpServer` 对象的 `this` 指针。

所以创建 `Session` 时，程序显式传入了配置和其他服务的引用：

```cpp
Session(std::uint64_t id,
        int socket,
        const AppConfig& config,
        DatabaseWriter& database,
        WebSocketServer& websocket,
        InferenceEngine& inference);
```

`Session` 能使用这些服务，是因为构造时保存了这些引用，而不是因为它继承了 `TcpServer`。

## 九、总结

```cpp
class TcpServer::Session
```

表示：

> 在类外部定义 `TcpServer` 内部的嵌套类 `Session`。

本项目采用这种写法，是为了：

```text
头文件保留接口
cpp 文件隐藏实现
减少编译依赖
保护内部细节
保持 TcpServer 结构清晰
```
